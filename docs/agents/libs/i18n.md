# i18n

> Frontend strings live in `src/shared/i18n/en.ts` (the base `Dict`) and `ko.ts` (typed `: Dict`, so a missing key fails `yarn typecheck`). Components read them with `const { t } = useI18n()`. Native labels (tray, app menu) live in `src-tauri/src/app/i18n.rs`. The preference (`system` | `en` | `ko`) is stored in `settings.locale`.

## Adding text

1. Add the key to `en.ts`, nested by area (`settings`, `updates`, …). Use a function for interpolation: `version: (v: string) => \`Version ${v}\``.
2. Add the same key to `ko.ts`. `yarn typecheck` fails until you do.
3. In the component: `const { t } = useI18n();` (under `// hooks`), then `t.area.key`.

Never hardcode user-visible text in a component. Language names in the language picker stay in their own language (`한국어`, `English`).

## Resolution

- `resolveLocale(pref, navigator.language)` (`src/shared/i18n/locale.ts`, unit-tested): `system` → `ko` if the OS language starts with `ko`, otherwise `en`.
- Rust uses the same rule in `app::i18n::resolve`, reading the OS language through `sys-locale`.
- `I18nProvider` sets `<html lang>` and listens for `settings://locale-changed`. Rust's `set_locale` also rebuilds the tray and app menu.

## Native labels

`app/i18n.rs` holds a `Labels` struct per language. When you add a tray or menu item, add its label to both languages and use `i18n::current(app)` when building the menu. Native window titles follow too: `window::refresh_titles` sets the settings window title, at startup and on every `set_locale`. The main window keeps the product name.

## Adding a language

1. `src/shared/i18n/<code>.ts` typed `: Dict`. Register it in `dicts` (`index.ts`) and the `Locale` type (`locale.ts`).
2. Add it to `LocalePref` in `settings.dto.ts` and to `LanguageSwitcher`.
3. Rust: add a `LocalePref` variant (`domain/settings/model.rs`), a `Labels` set and a `resolve` arm (`app/i18n.rs`), with tests.
