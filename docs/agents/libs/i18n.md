# i18n

> Two languages: English and Korean. Frontend strings live in `src/shared/i18n/en.ts` (the base `Dict`) and `ko.ts` (typed `: Dict`, so a missing key fails `yarn typecheck`). Components read them with `const { t } = useI18n()`. Native text (tray, app menu, quit dialog, settings window title) lives in `src-tauri/src/app/i18n.rs`. The preference (`system` | `en` | `ko`) is `settings.general.ui_language`.

## Adding text

1. Add the key to `en.ts`, nested by area (`settings`, `update`, `errors`, …). Use a function for interpolation: `version: (v: string) => \`Version ${v}\``.
2. Add the same key to `ko.ts`. `yarn typecheck` fails until you do.
3. In the component: `const { t } = useI18n();` (under `// hooks`), then `t.area.key`.

Never hardcode user-visible text in a component. Language names in the language picker stay in their own language (`한국어`, `English`).

## Resolution

- `resolveLocale(pref, navigator.language)` (`src/shared/i18n/locale.ts`, unit-tested): `system` → `ko` if the OS language starts with `ko`, otherwise `en`.
- Rust uses the same rule in `app::i18n::resolve_with`, reading the OS language through `sys-locale`. Unknown values (including the dropped `ja`) follow the OS language; `Settings::normalize` also rewrites a stored `ja` to `system`.
- `I18nProvider` reads the language from the `['settings']` cache (kept current by `settings://changed`) and sets `<html lang>`. Rust's `patch_and_notify` relabels the tray, the app menu and the settings window title when the language changes.

## Native labels

`app/i18n.rs` holds one `Labels` struct per language. When you add a tray, menu or dialog item, add its label to both languages and build it with `i18n::current(app)`. The main window title stays `kiri`.

## Adding a language

Only `en` and `ko` are supported; adding one is a product decision — ask the user first. If approved:

1. `src/shared/i18n/<code>.ts` typed `: Dict`. Register it in `dicts` (`index.ts`) and the `Locale` type (`locale.ts`).
2. Add it to `LocalePref` in `settings.dto.ts` and to `LOCALES` in `GeneralTab.tsx`.
3. Rust: add it to `UI_LANGUAGES` (`domain/settings/model.rs`), a `Lang` variant, a `Labels` set and a `resolve_with` arm (`app/i18n.rs`), with tests.
